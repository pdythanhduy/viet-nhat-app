already exists at `device-qa-v1.3.2.md`. This is a desk audit looking for obvious issues.

## 🔴 Findings — high impact

### F1. Mail Translate has zero entry points

**Confirmed by grep:** no file under `src/screens/Home*`, `src/screens/Admin*`, or
`src/screens/Settings*` references `MailTranslateIntro` or `MailCapture`. The only
references are the 3 Mail screens themselves + `AppNavigator.tsx` (route registration).

**Impact:** Phase 1 mock is invisible. All `mail_*` analytics events will read 0 forever.

**Fix:** ~30 min. Add a quick-action card on HomeScreen → `MailTranslateIntro`.

Documented in `mail-translate-audit.md` section 2.

## 🟠 Findings — medium impact

### F2. JapaneseScreen quickRow now has 5 buttons (added "Hôm nay" in v1.5.0)

Style: `quickRow: { flexDirection: 'row', flexWrap: 'wrap' }` + `quickBtn: { minWidth: '45%' }`.

Math: 5 buttons × 45% min width = 225% needed → wraps to 2 rows of 2 + last button alone.

**Risk on iPhone SE (320pt-375pt):** Button content "Trắc nghiệm" (10 chars) and "Đọc Truyện"
(10 chars with diacritic) might wrap text inside the button on narrow screens. Visual
crowding likely.

**Suggested verification:** Open Expo Go on iPhone SE simulator, navigate to Japanese tab,
look at quickRow. If text wraps awkwardly, options:
- Shorten labels: "Trắc nghiệm" → "Quiz" (already 4 chars), "Đọc Truyện" → "Truyện"
- Drop one of the 4 secondary buttons (BJT vs Đọc Truyện vs Bảng chữ — pick 3)
- Make quickRow horizontally scrollable instead of wrap

**Effort to fix if needed:** 15 min.

### F3. `Animated.timing` in DailyRitualScreen `useNativeDriver: true` with opacity

The done-stage fade-in uses `Animated.timing(fadeAnim, { toValue: 1, duration: 320, useNativeDriver: true })`.
Animating opacity with native driver is supported — should be fine. **No action needed**,
flagging only because animation behavior is hard to assert from desk audit.

## 🟡 Findings — low impact / cleanup candidates

### F4. Legacy analytics wrappers still in use

After Aptabase rewrite, these legacy wrappers are still called from existing files:

| Function | Called from | Status |
|---|---|---|
| `logScreenView` | AppNavigator.tsx | Used (routes Home → home_view, others ignored) |
| `logGuideOpened` | AdminDetailScreen.tsx | Used (routes to track('guide_open')) |
| `logQuizStarted/Completed` | BJTQuiz, JapaneseKanaQuiz, JapaneseQuiz, DailyRitual | Used (DailyRitual routes to ritual_*) |
| `logBookmarkToggled` | AdminDetailScreen, DailyLifeDetailScreen | **No-op** (intentionally not in EventMap) |
| `logHtmlExported`, `logJLPTQuizCompleted`, `logWordSaved`, `logStoryStarted`, `logStoryCompleted`, `logSearchPerformed`, `logHomeSearchPressed`, `logHomeQuickActionPressed`, `logAdminSituationPressed` | various | **No-op, no caller** found in grep — likely dead |

**Action:** Could delete the truly-unused no-ops (`logHtmlExported`, `logJLPTQuizCompleted`,
`logWordSaved`, `logStoryStarted`, `logStoryCompleted`, `logSearchPerformed`,
`logHomeSearchPressed`, `logHomeQuickActionPressed`, `logAdminSituationPressed`) since the
rewrite confirms they don't track anything. But this is housekeeping, not urgent.

**Caveat:** The grep showed call sites for SOME of these (e.g. `logHomeQuickActionPressed`
exists in HomeScreen.tsx). Re-grep before deleting. Actually:

```
grep result for legacy bookmark/html/etc:
- src/screens/AdminDetailScreen.tsx (logBookmarkToggled, logHtmlExported)
- src/screens/DailyLifeDetailScreen.tsx (logBookmarkToggled)
- src/utils/analytics.ts (the definitions)
```

So `logBookmarkToggled` and `logHtmlExported` ARE used. Don't delete those even if they
no-op — still imported. Decision: keep all legacy wrappers for now (no-op cost is zero).

### F5. Network error handling on remote content loader is solid

`src/services/contentLoader/remote.ts` already has:
- AbortController + 5s timeout
- try/catch swallowing all errors → returns null
- Caller falls back to bundled content

**No action needed.** Behavior on offline/timeout is correct.

### F6. Daily Ritual quiz state isn't reset on screen blur

If user starts a quiz, navigates away mid-flow, then comes back, they see the same quiz
state (currentIndex, selectedIndex). Probably desired (don't lose progress) but could
confuse if they think the screen is broken. Minor, won't fix.
