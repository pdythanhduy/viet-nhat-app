## 1. Pre-flight verification (safe to run, read-only)

```bash
# 1.1 Confirm we're on the right commit
git log --oneline -1
# Expected: ae8e555 feat(retention): "Đã xem gần đây" Home surface + storage util (#62)
# (or a newer HEAD if more PRs have landed after this doc was written)

# 1.2 Confirm versions
grep '"version"' package.json
# Expected: "version": "1.5.0",
grep -A 1 '"version"' app.json | head -3
# Expected: app.json version = "1.5.0"

# 1.3 Confirm no uncommitted changes
git status

# 1.4 Confirm EAS auth + project linkage
npx eas whoami
# Expected: the maintainer's Expo account, not "Not logged in"

npx eas project:info
# Expected: matches @thanhduy/viet-nhat-app or whatever the linked slug is

# 1.5 Confirm Aptabase key is set in app.json (not placeholder)
node -e "const c = require('./app.json'); console.log('aptabaseAppKey:', c.expo?.extra?.aptabaseAppKey ?? 'MISSING')"
# Expected: a real key starting with A-EU-... (NOT 'PLACEHOLDER' / undefined / empty)

# 1.6 Final pre-build verify
npm run verify
# Expected: typecheck + test:ci + verify:content all green
```

If any 1.x step fails → DO NOT proceed.

## 3. EAS production build (BILLABLE — requires explicit go)

```bash
# 3.1 iOS production build (builds against latest main)
npx eas build --platform ios --profile production --non-interactive

# 3.2 Android production build
npx eas build --platform android --profile production --non-interactive

# Or both at once (parallel queue)
npx eas build --platform all --profile production --non-interactive
```

EAS will auto-increment buildNumber (iOS) and versionCode (Android) per the `production.autoIncrement: true` setting in `eas.json`. The remote `appVersionSource` ensures EAS owns the version.

Monitor build progress:
```bash
npx eas build:list --limit 5
# Or use the URL printed at submit time → https://expo.dev/accounts/.../builds/...
```

Expected wait: 15-30 min per platform.

**Rollback before submit**: cancel via dashboard or `npx eas build:cancel <build-id>`. No App Store impact.

## 4. App Store / Play Store submission (FINAL — irreversible without a new build)

After §3 builds finish successfully AND smoke test on the build artifact (TestFlight / internal track) passes:

```bash
# 4.1 iOS submit to App Store Connect
npx eas submit --platform ios --latest --non-interactive
# Uses ascAppId 6762459919 per eas.json

# 4.2 Android submit
npx eas submit --platform android --latest --non-interactive
```

Then in App Store Connect / Play Console:
- Paste release notes from `docs/v1.5.0-changelog.md` → "App Store release notes" section
- Confirm screenshots (or accept v1.4 carry-over)
- Hit "Submit for review"

**Rollback after submit**:
- App Store: "Reject Binary" or "Reject this version" before review starts. After review: pull the version back if still pending release.
- Play Store: halt rollout from console.
- Worst case: revert to v1.4.0 tag `d590a5a`, address feedback in v1.5.1.

## 6. If smoke test (or App Review) fails

| Scenario | Action |
| --- | --- |
| Smoke test catches a bug on the EAS build | Fix on a `fix/v1.5.0-*` branch → merge → bump build via new EAS build (no version bump needed, just auto-increment) |
| App Store rejection (e.g., metadata, screenshots) | Address in App Store Connect without new build if it's metadata-only |
| App Store rejection (binary issue) | Fix → new EAS build → resubmit. Version stays 1.5.0; buildNumber auto-increments |
| Critical post-release crash | Roll forward with v1.5.1 hotfix; do NOT retract v1.5.0 unless legally compelled |

The v1.4.0 tag `d590a5a` is the rollback anchor — it was App-Review-approved on the same bundle ID.
