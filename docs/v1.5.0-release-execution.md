## 1. Exact EAS commands

### 1.1 Build (BILLABLE — gated)

```bash
# iOS production build
npx eas build --platform ios --profile production --non-interactive

# Android production build
npx eas build --platform android --profile production --non-interactive

# Or both in parallel queue
npx eas build --platform all --profile production --non-interactive
```

EAS auto-increments `buildNumber` (iOS) and `versionCode` (Android) per `eas.json` (`production.autoIncrement: true`).
`appVersionSource: "remote"` — EAS owns the version; `app.json` version is canonical for display only.

### 1.2 Monitor

```bash
npx eas build:list --limit 5
# Or open the URL printed at submit time → https://expo.dev/accounts/.../builds/...
```

Wait: 15-30 min per platform.

### 1.3 Submit (FINAL — irreversible without new build)

```bash
# iOS to App Store Connect (uses ascAppId 6762459919 per eas.json)
npx eas submit --platform ios --latest --non-interactive

# Android to Play Console
npx eas submit --platform android --latest --non-interactive
```

After submit, in the respective stores:
- Paste release notes from `docs/v1.5.0-changelog.md` "Long version"
- Confirm screenshots (v1.4 carry-over OR new — see §4 of `v1.5.0-app-store-audit.md`)
- "Submit for review"

## 5. Rollback plan

### If smoke test fails

Fix on a `fix/v1.5.0-*` branch → merge → no version bump needed → trigger new EAS build → buildNumber auto-increments.

### If EAS build fails

Read the EAS dashboard error. Common causes:
- Missing asset (icon / splash) — check `app.json` paths
- Native module mismatch with SDK 54 — should not occur (no native changes since v1.4 ship)
- Provisioning profile (iOS) — re-run `eas credentials --platform ios`
- Keystore (Android) — `eas credentials --platform android`

### If App Store rejects

- **Metadata issue** (description, screenshots): fix in App Store Connect, no new build needed
- **Binary issue** (privacy, permissions, crash on review device): fix → new EAS build → resubmit. Version stays 1.5.0; buildNumber auto-increments. Apple keeps the rejection record but doesn't penalize re-submission

### If post-release crash on live users

- **Soft crash (low %)**: hotfix in v1.5.1 within 1 week
- **Hard crash (high % / data loss)**: emergency revert. Apple expedited review for v1.5.1 hotfix referencing the crash root cause. Do NOT retract v1.5.0 binary unless compelled

### Rollback anchor

**v1.4.0 tag `d590a5a`** is the rollback anchor — App-Review-approved on the same bundle ID. Worst case:

```bash
git revert <each post-v1.4.0 merge commit>  # or
git reset --hard d590a5a  # destructive — coordinate with team first
# Re-EAS build against the reverted main
```

## 6. "DO NOT RELEASE IF" — hard refusals

| Condition | Why |
|---|---|
| Device smoke test has any Blocker-severity issue | Risk of App Review rejection or user-visible crash |
| `npm run verify` not clean on the exact HEAD being built | Tests are the safety net |
| Aptabase key is placeholder or missing | Analytics blind for first weeks = no learning signal |
| Git working tree has uncommitted changes to source files | Build won't reproduce; rollback gets harder |
| v1.4.0 tag `d590a5a` has been deleted or rewritten | Lost rollback anchor |
| TestFlight / internal-track build was NOT smoke-tested separately from the dev build | Different artifact, different bugs |
| App Store screenshots are still v1.3 era (not v1.4 or new) | Misleads users about what the app does today |
| Aptabase EU instance is mis-configured to US | Privacy posture diverges from docs |
| EAS account has unrelated builds queued ahead of ours | Wait — `npx eas build:list` to confirm queue |
| Any new dependency added in last 72h that wasn't reviewed | Native module surprises |

## 7. App Store submission sequence

### iOS (App Store Connect)

1. EAS build completes → artifact uploaded to App Store Connect automatically (eas.json submit profile)
2. Open App Store Connect → My Apps → Cẩm Nang Việt Nhật → TestFlight tab → confirm new build appears
3. Run device smoke test ON THE TESTFLIGHT BUILD (not the dev Metro build)
4. If smoke passes: switch to App Store tab → "+ Version" → 1.5.0
5. Fill: What's New (paste from `v1.5.0-changelog.md` Long version)
6. Confirm screenshots (carry v1.4 OR upload new per `v1.5.0-app-store-audit.md`)
7. Confirm app review notes (no special demo steps needed; no auth)
8. "Add for Review" → "Submit for Review"
9. Expected: review queue 24-48h

### Android (Play Console)

1. EAS build completes → artifact uploaded to Play Console automatically
2. Internal testing track → confirm new build appears
3. Smoke test on internal-track install
4. If smoke passes: Production track → "Create new release"
5. Paste release notes
6. Same screenshot decision as iOS
7. "Review release" → "Start rollout to Production"
8. Default: phased rollout 20% → 100% over 7 days. Can stop rollout from console if regression appears
